1. Descripcion General del Proyecto

EcoEmpack es una aplicacion web full stack desarrollada para una empresa de empaques ecologicos cuya mision es ayudar a las personas a realizar un detox del plastico y protegerse de los microplasticos. La aplicacion presenta el catalogo de productos, informacion cientifica sobre microplasticos y un sistema de administracion con autenticacion segura.

CaracteristicaDetalle
Tipo de aplicacionWeb Full Stack (SPA parcial + API REST)
Entorno del backendNode.js v18+ con Express.js v4
Base de datosMongoDB (con Mongoose ODM)
AutenticacionJWT (JSON Web Tokens) + bcryptjs
FrontendHTML5 + CSS3 + JavaScript Vanilla (ES6+)
Puerto del servidor3000 (configurable via .env)

Objetivos del Proyecto

  • Configurar un entorno de desarrollo Node.js con npm y variables de entorno con dotenv
  • Desarrollar un frontend responsivo con HTML, CSS y JavaScript
  • Construir una API RESTful en Express.js con operaciones CRUD completas
  • Implementar autenticacion basada en JWT con contrasenas encriptadas con bcrypt
  • Conectar el backend a una base de datos MongoDB mediante Mongoose
  • Desplegar una version preliminar en entorno local y en la nube

2. Arquitectura de la Aplicacion

La aplicacion sigue una arquitectura cliente-servidor de tres capas:

USUARIO (Navegador) ⟶ HTTP Request ⟶ EXPRESS SERVER (Puerto 3000) ⟶ Mongoose ⟶ MONGODB (BD)
Capa de Presentacion                  Capa de Negocio / API                  Capa de Datos

Flujo de una peticion autenticada

/* Ejemplo: Admin crea un nuevo producto */

1. Frontend envia:
   POST /api/products
   Headers: { Authorization: "Bearer eyJhbGciOiJIUzI1NiJ9..." }
   Body: { nombre: "Bolsas Kraft", precio: 0.45 }

2. Middleware auth.js intercepta la peticion:
   - Extrae el token del Header
   - jwt.verify(token, JWT_SECRET) → decodifica el payload
   - Busca el usuario en MongoDB con decoded.id
   - Agrega req.usuario = { id, email, rol: "admin" }
   - Llama next() para continuar

3. Middleware soloAdmin verifica rol:
   - req.usuario.rol === "admin" → next()

4. Route handler crea el producto:
   - Product.create(req.body)
   - MongoDB guarda el documento
   - Responde con { success: true, product: {...} }

El middleware protegerRuta se ejecuta antes de cada ruta protegida:

// 1. Leer el token del header Authorization: Bearer <token>
// 2. jwt.verify(token, JWT_SECRET) → lanza error si expirado/invalido
// 3. User.findById(decoded.id) → confirmar que el usuario existe en BD
// 4. req.usuario = usuario → disponible en todas las rutas siguientes
// 5. next() → continuar hacia el route handler

8. Endpoints de la API RESTful

URL base: http://localhost:3000/api  |  Produccion: https://ecoempack-api.onrender.com/api

Autenticacion — /api/auth

POST /api/auth/register Publica Crear nueva cuenta

Body (JSON): { "nombre": "Ana", "apellido": "Lopez", "email": "ana@test.com", "password": "miPass123" }

Respuesta 201: { "success": true, "token": "eyJhbGci...", "user": { "id", "nombre", "email", "rol" } }

Error 400: Si el email ya existe o los datos son invalidos.

POST /api/auth/login Publica Iniciar sesion

Body (JSON): { "email": "ana@test.com", "password": "miPass123" }

Respuesta 200: { "success": true, "token": "eyJhbGci...", "user": {...} }

Error 401: Credenciales incorrectas.

GET /api/auth/perfil Protegida — JWT Ver mi perfil

Header requerido: Authorization: Bearer <token>

Respuesta 200: { "success": true, "user": { "nombre", "email", "rol" } }

Productos — /api/products

GET /api/products Publica Listar todos los productos

Query params opcionales: ?categoria=bolsas   ?biodegradable=true

Respuesta 200: { "success": true, "count": 6, "products": [...] }

GET /api/products/:id Publica Ver un producto por ID

Params: :id = ObjectId de MongoDB (ej: 507f1f77bcf86cd799439011)

Respuesta 200: { "success": true, "product": { ... } }

Error 404: Producto no encontrado.

POST /api/products Protegida — Admin Crear producto

Header: Authorization: Bearer <token-admin>

Body: { "nombre", "descripcion", "categoria", "precio", "stock", "biodegradable" }

Respuesta 201: { "success": true, "product": { _id, nombre, ... } }

PUT /api/products/:id Protegida — Admin Actualizar producto

Header: Authorization: Bearer <token-admin>

Body: Solo los campos a actualizar: { "precio": 200 }

Respuesta 200: { "success": true, "product": { ...actualizado } }

DELETE /api/products/:id Protegida — Admin Eliminar producto (soft)

Header: Authorization: Bearer <token-admin>

Nota: Implementa soft delete: cambia activo: false en vez de borrar el registro. Esto preserva el historial de datos.

Respuesta 200: { "success": true, "message": "Producto eliminado correctamente." }

9. Sistema de Autenticacion JWT

El sistema usa autenticacion stateless basada en JWT. No se almacenan sesiones en el servidor.

Flujo completo del ciclo de autenticacion

/* REGISTRO */
POST /api/auth/register
  → Validar datos de entrada
  → User.create() → pre-save hook encripta la contrasena con bcrypt
  → jwt.sign({ id: usuario._id }, JWT_SECRET, { expiresIn: '7d' })
  → Responder con token + datos del usuario

/* LOGIN */
POST /api/auth/login
  → User.findOne({ email }).select('+password')
  → bcrypt.compare(passwordIngresada, passwordHash) → boolean
  → Si correcto: jwt.sign() → devolver token
  → Si incorrecto: 401 Unauthorized

/* PETICION PROTEGIDA */
GET|POST|PUT|DELETE /api/products
  → Header: Authorization: Bearer <token>
  → middleware/auth.js:
      jwt.verify(token, JWT_SECRET) → { id, iat, exp }
      User.findById(decoded.id) → confirmar usuario activo
      req.usuario = usuario
      next()
  → Route handler ejecuta la logica
Seguridad de las contrasenias: bcrypt aplica un algoritmo de hashing con "salt" aleatorio. La misma contrasena produce hashes diferentes en cada ejecucion, lo que impide ataques de tabla arcoiris (rainbow tables). El parametro rounds=10 hace que un ataque de fuerza bruta sea computacionalmente impracticable.
Variables de entorno criticas: JWT_SECRET y MONGODB_URI jamas deben estar en el codigo fuente. Se almacenan exclusivamente en el archivo .env que esta incluido en .gitignore.

📚 11. Guía Explicativa “For Dummies”

Esta sección explica cada tecnología y concepto del proyecto en lenguaje simple, con analogías del mundo real. No se requiere experiencia previa.

🆕 ¿Qué estamos construyendo?

Una aplicación web full stack tiene dos partes que trabajan juntas:

🍽️ Anología del restaurante:
• El Frontend = el salón del restaurante (lo que ve el cliente)
• El Backend = la cocina (donde se prepara todo, invisible al cliente)
• La Base de Datos = la despensa (donde se guardan los ingredientes / datos)
• La API = el mesero (quien lleva mensajes entre cocina y salón)

💻 Tecnologías explicadas una por una

TecnologíaQué es en palabras simplesAnalogía
Node.js JavaScript corriendo en tu computadora, no en el navegador. Permite usar JS para crear el servidor. Es como sacar a JS del navegador y ponerlo a trabajar como empleado en la cocina.
Express.js Un framework que facilita crear servidores y rutas con muy poco código. Node.js es una caja de herramientas. Express es el cinturón organizado donde cada herramienta ya tiene su lugar.
MongoDB Base de datos que guarda información en formato JSON (como objetos de JavaScript), sin tablas fijas. MySQL es una hoja de Excel muy rígida. MongoDB es una colección de tarjetas de notas donde cada tarjeta puede tener diferente información.
Mongoose Puente entre Node.js y MongoDB. Permite definir “plantillas” (schemas) para que los datos siempre tengan el formato correcto. Si MongoDB es una bodega sin orden, Mongoose es el sistema de organización que dice: “aquí van los zapatos, allá los libros”.
JWT Un “pasaporte digital” que el servidor le da al usuario después de iniciar sesión. En cada petición protegida se muestra ese pasaporte. Cuando entras a un parque de diversiones, pagas y te ponen una pulsera. JWT es esa pulsera: la muestras en cada atracción sin volver a pagar.
bcryptjs Convierte la contraseña “hola123” en algo como “$2a$10$Kxm...” que es imposible de revertir. Las contraseñas nunca se guardan en texto plano. Es como pasar tu mensaje por una picadora de papel. Puedes confirmar que algo fue picado, pero no reconstruirlo.
dotenv Lee un archivo .env con información secreta (contraseñas, claves) y la inyecta como variables. Ese archivo nunca se sube a GitHub. En vez de publicar tus llaves en Facebook, las guardas en un llavero privado y dot env las recupera solo cuando tu programa las necesita.
CORS Permiso que da el servidor para aceptar peticiones de otro origen (por ejemplo: el frontend en puerto 5500 hablando con el backend en puerto 3000). Sin CORS, el navegador bloquea las peticiones entre dominios/puertos diferentes como medida de seguridad. CORS es la lista de invitados que da acceso.

🔄 ¿Qué es una API RESTful?

API = intermediario que permite que dos programas se comuniquen. REST = conjunto de reglas para diseñar esa comunicación usando verbos HTTP:

Verbo HTTPQué significaEjemplo en este proyecto
GETObtener / Leer informaciónVer todos los productos del catálogo
POSTCrear / Enviar información nuevaRegistrar un nuevo usuario o producto
PUTActualizar información existenteCambiar el precio de un producto
DELETEEliminar informaciónDesactivar un producto del catálogo

📊 ¿Qué son las operaciones CRUD?

CRUD = Create, Read, Update, Delete — las 4 operaciones básicas de cualquier sistema que maneja datos.

Toda aplicación de gestión (tienda, red social, banco) en el fondo hace solo estas 4 cosas con sus datos. En este proyecto: crear productos, leerlos, editarlos y eliminarlos.

🔒 ¿Cómo funciona JWT paso a paso?

/* Paso 1 */ Usuario escribe email + contraseña en el formulario
/* Paso 2 */ Frontend envía POST /api/auth/login al backend
/* Paso 3 */ Backend busca el usuario en MongoDB
/* Paso 4 */ bcrypt.compare(pass_ingresada, hash_en_BD) → true o false
/* Paso 5 */ Si es correcto: jwt.sign() genera el token y lo envía
/* Paso 6 */ Frontend guarda el token en localStorage
/* Paso 7 */ En peticiones futuras el frontend envía: Authorization: Bearer <token>
/* Paso 8 */ Middleware auth.js verifica el token antes de dar acceso

📄 ¿Por qué usamos dotenv y variables de entorno?

⚠️ Problema: Si escribes tu contraseña de la base de datos directamente en el código y lo subes a GitHub, cualquier persona en el mundo puede verla.

✅ Solución: Guardas los datos sensibles en un archivo .env que nunca se sube a GitHub (está en .gitignore). El código solo lee process.env.MONGODB_URI y dotenv lo conecta automáticamente con el valor real del .env.

📱 ¿Qué es localStorage?

Es una pequeña base de datos que tiene cada navegador. Permite guardar texto (como el token JWT) que persiste aunque cierres la pestaña. Se accede con:

localStorage.setItem('token', jwt) // guardar
localStorage.getItem('token') // leer
localStorage.removeItem('token') // borrar (logout)

🏠 ¿Qué es un puerto?

Tu computadora tiene miles de “puertas” numeradas (puertos). Cada servicio usa una diferente:

• Puerto 80 → sitios web normales (HTTP)
• Puerto 443 → sitios web seguros (HTTPS)
• Puerto 3000 → nuestro servidor Express
• Puerto 5500 → Live Server de VS Code (el frontend)

Por eso necesitamos CORS: el frontend en :5500 quiere hablarle al backend en :3000, y el navegador por defecto bloquea esa comunicación entre puertos diferentes.
